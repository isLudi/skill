## 计算

在同一报表的期次、渠道及当前主管、年级、学部等筛选范围内，先按顾问账号汇总综合营收，再计算：

`破蛋率 = 营收严格大于0的顾问去重人数 / 同范围顾问去重总人数`。

- 营收取收款／income，包含该交易期次内当期、往期线索产生的收入；不扣退费，不使用净收款／promit，不使用当期收款代替综合营收。
- 同一顾问有多个用户、多个订单、多个科目或者多条记录，只计1名顾问。顾问营收必须先合计，再与0比较。
- 分母包含同范围无营收的顾问。本机推送沿用现有过程数据中的顾问账号全集、渠道范围及展示门槛；不把分母缩小为出单顾问，也不扩大到无来源证明的在岗人员全集。
- 分年级明细分别计算；渠道或总计行合并该层级范围，按账号去重并重新汇总各账号营收后计人，不相加年级人数、不平均明细百分比。同一账号在多个年级或子渠道中出现，合计只计1人。
- 单顾问范围的指标为0%或100%。无顾问时保留空值／无可计算展示，不除以0。
- 金额合计使用十进制定点语义，避免0.1+0.2-0.3的浮点误差被判定为正营收。

等价计算分两层，不能将内层SUM直接嵌套在COUNT DISTINCT中：

```sql
-- scoped_advisor_revenue必须先应用当前报表筛选，且每个顾问账号恰好一行。
select
    sum(case when advisor_revenue > 0 then 1 else 0 end)
        / nullif(cast(count(*) as double), 0) as advisor_breakthrough_rate
from scoped_advisor_revenue
```

## 与旧字段的区别

2460的原始`podan`及推送Base的“破蛋人数标记”仍表示折算净收为正的成交用户标记，保留其物理含义，不能重命名为顾问破蛋人数，也不能直接除以顾问人数。`v_lead`仍为线索量，其他转化率继续使用它，不能为修正破蛋率而改写该字段。

2026-11-22本地13:52批次样例：本地化／杜孝忠／高一共有6名顾问，营收>0的顾问2名，成交用户破蛋标记3个，有效线索225。新破蛋率为2/6=33.3%，旧值3/225=1.3%。样例只证明该报表6名接量顾问范围，不推断额外人员全集。
