# 青橙 ASR 分区与通话原文可用性探查

## 探查问题与边界

核对数据地图标注的“保留 30 天”是否等同于青橙历史通话 ASR 原文不可用，并验证 ASR 分区字段 `dt` 与通话发生日期的关系。查询限定在青橙顾问通话 URL 的匹配统计；知识库不保存录音 URL、消息或通话文本。

## 最新验证状态（2026-10-02）

- 近期 ASR 分区实测包含历史任务重复快照，覆盖测试中的 2025 年通话；“30 天”不能解释成历史通话原文只保留 30 天。
- 主表单快照候选 Query ID `1610802459` 已在 145 秒成功取出完整 15 天结果。348 行、139 个用户、16,232 条消息、518 通电话及 518 份 ASR 原文；与独立基线 Query ID `1610797680` 的逐行、逐消息和逐通话比较零差异。
- 这证明当前任务存在使用有权限主表的实现路径，不依赖 ODS 表。模板平台解析兼容性与发布后查询仍待完成；不得将 SQL 候选成功写成模板已上线。

## 实测证据（2026-10-01）

- 数据地图表 ID `29197`：`one_dw.dwd_mkt_ai_assistant_asr_record_df` 标记为增量表、保留期 `30天`、约 `978.16GB`，元数据更新时间 2026-09-29。这是平台登记信息，不单独证明历史记录实际可读性。
- Query ID `1609725265`，分区 `dt='20260831'`：查询成功，分区总行数 `154,975,981`；青橙匹配 ASR 行 `44,228`，成功且解析文本非空 `42,497`；匹配通话 URL `36,819`，有成功解析记录的 URL `36,818`。该分区在查询日约为 31 天前，说明至少有一个超过 30 天的分区仍可读。
- Query ID `1609738828`：核对上述分区里的青橙 URL 与通话发生时间，成功解析的 URL 中 `36,809` 个的通话日期不等于 ASR `dt`；对应通话时间从 2024-01-08 到 2026-08-31。因此旧通话文本可以出现在较新的 ASR 任务分区，`dt` 不能当作通话日期，按 `dt = call_date` 会漏历史。
- Query ID `1609904503`，分区 `dt='20260801'`：查询日志确认执行成功、`rows=0`，即整分区没有返回记录；该日期约为查询日 61 天前。
- Query ID `1609768899`，分区 `dt='20250831'`：查询日志确认执行成功、`rows=0`。该分区也没有记录可供青橙 URL 匹配。

## 结论

不能把“保留 30 天”解释成“所有超过 30 天的通话原文都不可读”：2026-08-31 分区在约 31 天后仍有青橙可用 ASR，且匹配到 2024 年通话。也不能据此声称全历史都完整保留：2026-08-01 与 2025-08-31 分区为空，单次样本无法判断是已清理、当日从未写入还是历史回填落在其他 `dt` 分区。

模板应通过非空 `call_url = origin_file_url` 关联通话原文，过滤 `state=2` 和非空 `parsed_content`；不要使用固定“最近 30 天”分区下界，也不要将 ASR `dt` 作为通话日期。若使用按通话时间计算的动态分区下界，必须确保下界不会裁掉晚到/回填的 ASR 任务；该边界尚未由全量历史样本证明。当前证据只能支持“至少有一部分早期通话文本可取回”，不能承诺每条线索从首次接触起的所有 ASR 原文均齐全。
