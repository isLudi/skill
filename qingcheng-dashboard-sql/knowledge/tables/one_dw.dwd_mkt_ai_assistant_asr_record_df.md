# one_dw.dwd_mkt_ai_assistant_asr_record_df

## 1. 中文名称

语音通话 ASR 记录（天工数据地图表 ID `29197`）。

## 2. 表用途

保存录音解析任务及解析文本。青橙项目部沟通明细通过通话记录 `call_url` 与 `origin_file_url` 候选关联；只有状态成功且解析文本非空的记录可作为 ASR 原文。

## 3. 数据粒度

近期每日分区实测表现为累计任务快照；同一 ASR 任务可重复出现在不同 `dt`。同一录音 URL 也可能匹配多条任务，按成功且非空文本过滤，并按 `update_time`、`id` 取最新可用文本，避免放大通话量、时长及原文拼接。该粒度结论基于青橙匹配样本，尚未取得 ETL 定义证明全表生成方式。

## 4. 查询引擎

Presto。

## 5. 分区字段

字段、类型及平台说明由天工数据地图同步命令维护。`dt` 是 ASR 表自身的天级分区；当前实测已证明它不能直接当作通话发生日期使用。

## 6. 强制范围限定字段

- 本表没有青橙部门字段。先以青橙线索和顾问沟通记录限定录音 URL，再关联本表；不要把全表行解释为青橙数据。

## 7. 字段清单

字段、类型和字段说明由 `usql-web-query-operator sync-datamap-fields --target-skill qingcheng` 从天工数据地图维护；不得手工编写字段目录。

## 8. 常用过滤条件

- `state = 2` 且 `parsed_content` 非空、非空串表示有可用的解析文本。
- 不使用固定最近 30 天的 `dt` 下界裁剪青橙沟通历史；按验证过的 ASR 记录时间/分区关系和目标录音 URL 设计查询。

## 9. 常用 join key

- 候选关联：`service_dw.ods_service_ai_ones_business_copilot__call_record_df.call_url = origin_file_url`。两端须排除空 URL；ASR 侧需先按经验证的任务取舍规则归并。

## 11. 注意事项

- 数据地图表 ID 29197 当前标记增量表、保留期 30 天、约 978.16GB（更新时间 2026-09-29）。青橙实测中，dt='20260831' 分区约 31 天后仍有 42,497 行成功非空 ASR；dt='20260801'（约 61 天前）及 dt='20250831' 查询成功但返回 0 行。登记保留期不是单条历史通话文本可用性的完整判据，也不证明全历史齐全。
- `dt` 是 ASR 表分区，不能当作任务创建日或通话发生日。Query ID 1609738828 在 dt='20260831' 的青橙成功解析样本中匹配到通话时间早至 2024-01-08；不得按 ASR dt = call_time 裁掉历史通话。
- 生产查询应按非空 origin_file_url 与目标青橙通话 URL 关联、过滤成功状态及非空文本，不加固定最近 30 天下界。若按通话时间动态裁剪分区，须先验证晚到/回填任务边界。
- 不在知识库留存录音 URL、消息原文、通话原文或 ASR 文本；仅记录聚合覆盖统计和 Query ID。
- 2026-10-02 的 16 天 cohort 探针显示，7/143 个用户的首次顾问接触早于按参数起始日计算的固定 ASR 分区下界；另有 1 个用户的有效通话早于该下界。不要用参数起始日替代业务上的首次接触时间裁剪历史。
- v7 的单次 ASR 表引用仍运行 12 分 39 秒后被取消，v8-v11 后续尝试也未成功。2026-10-02 v14 的单快照候选已在 145 秒返回完整 15 天结果；候选查询成功与模板发布成功必须分别验收。

### 2026-10-02 15 天候选性能复测

- 数据地图 DDL 复读确认存储格式为 Parquet、登记容量 978.16GB，`dt` 是唯一分区字段；没有登记 `origin_file_url` 索引。登记保留期仍为 30 天，但这不代表青橙每条历史通话的 ASR 覆盖情况。
- Query ID `1610536697`（v9）、`1610537986`（v10）、`1610539067`（v11）均使用 2026-09-17 至 2026-10-01 的 15 天窗口，分别在平台计时约 287、287、283 秒时仍未结束并被人工停止；客户端累计耗时分别约 293.5、288.89、289.203 秒。均无结果集，不通过 300 秒性能门槛。
- 三版分别调整了目标人群去重顺序、AI 通话关联、ASR 通话日动态 `dt` 下界；每个 SQL 文本中的六张源表各出现一次。没有执行计划，不能确认引擎运行时未重复物理扫描。
- 不加固定最近 30 天 `dt` 下界仍是要求。按通话日设置动态下界前须验证所有晚到任务分区均不早于该边界；已有样本支持较新任务分区包含早期通话，但不能证明所有历史任务的边界。
- SQL 性能仍未验收，模板未基于这些候选新计划或发布。当前可证事实只有：ASR 表大、Parquet、仅按 `dt` 分区；大扫描是待验证的性能瓶颈假设。
