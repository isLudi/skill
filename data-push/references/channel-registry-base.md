# 渠道配置中心 Base

当用户要把新增渠道需求交给运营填写，或把本地渠道配置汇总到多维表格时，使用本方案。Base 是协作入口和审计台账；`config/channels.json` 及其指向的部门配置仍是本地生产执行的唯一事实源。Base 记录不得直接绕过评审去改任务、发消息或启用调度。

## 两张表

### 运营填写

只放运营能确定且需要维护的业务信息：部门、渠道名称、数据源、目标群、周期、时段、维度、业务指标、展示门槛、提醒偏好和效果参考。运营不填写字段 ID、SQL、聚合公式、群 ID、open_id、脚本路径、重试实现或任务参数。

指标不得用一段逗号文本笼统代替。常见过程/转化指标使用多选字段逐项勾选；部门专属或尚未登记的指标在“其他指标”中每行填写一项，格式为“指标名称｜业务含义”。展示顺序单独选填，正式字段映射和计算公式由技术表补全。市场顾问部与青橙项目部可以选择完全不同的指标集合，不从另一个部门继承默认指标。

提醒另外填写 `播报层级`、`过程文字提醒名次`、`转化文字提醒名次`。三字段已进入“运营-指标与提醒”视图并在技术表有对应实时 lookup；可选值同时覆盖两个部门，但填写和执行须按[市场顾问部规则](departments/market_consultant.md)或[青橙规则](departments/qingcheng/local_broadcast_rules.md)独立解释。无该类报告选“不适用”。历史共用的 `并列处理` 只在适用的部门继续保留，不能代替两类报告各自的名次。

运营表至少提供两个简化视图：基础信息、指标与提醒。底层保留的迁移兼容或技术回填字段不进入这两个视图；不能因为视图隐藏就删除信息。

### 技术配置

工作流 `运营申请自动建立技术配置` 用于在新增运营申请时建立关联的“待评审”技术记录；运营不需要再次填写技术表。完成技术拆分后，每条实施记录代表一个明确的 `domain/execution_surface/deployment/target` 配置。双向关联字段 `关联运营申请` 连接运营表；部门、渠道名、目标群和提醒偏好等关键业务信息通过 lookup 实时展示；上线门禁与调度状态用公式汇总。可搜索的脚本参数拆列保存，完整配置同时写入 `配置JSON快照`，避免嵌套参数遗漏。公式字段 `Prompt拼接` 只输出记录定位、部门/渠道、原始匹配、目标群 ID、展示字段、提醒规则、周期/筛选和当前状态等核心参数，并给出 `lark-cli +record-get` 读取命令；机器路径、上游任务、哈希和完整 JSON 等细节不再重复拼接。每条新增或更新技术记录都会自动重新计算，不为单一渠道写特例。

技术表是机器参数仓和实施回执，不是第二张运营问卷。日常只使用三个视图：

`weekend_next_process_enabled` 与 `weekend_next_process_minimum_post_leads` 拆列保存周末下一期过程数据的路由和专用门槛；原 `minimum_post_leads` 保留本期转化及普通过程数据门槛，完整参数仍以 `配置JSON快照` 审计。

- `技术-待处理`：关联申请、部门、渠道、目标群、过程与转化指标、提醒偏好、实施状态、负责人和门禁结论。运营字段由 lookup 展示，不在技术记录中另存副本。
- `技术-验证上线`：预览、测试、源字段、群成员、试发、授权和调度状态。
- `技术-机器参数（维护）`：保留完整机器字段，仅供技术维护和审计。

运营填写完成后，先用 `scripts/read_channel_registry_request.py` 以 `record_id` 或申请编号直接只读运营记录，生成候选配置说明。能够从运营记录确定的部门、群、周期、维度、指标、门槛和提醒偏好不得要求技术重复填写；执行面、adapter、字段映射、脚本路径、错峰任务名和上游版本门禁仍由技术审阅后写入本地配置。候选说明不自动修改生产配置、不注册任务、不启用调度、不发送消息。

当前自动化边界仅为“建立并关联待评审技术记录”。读取运营申请、生成本地候选、业务 Skill 审阅、预览、授权、写入生产配置及启用调度仍是分离门禁；不得把 Base 工作流扩展成无人审阅的生产发布。

自动建单只对工作流实际捕获的新增申请生效，不追溯历史；当前触发控制也不能保证 API 批量创建后自动建单。批量补录或导入后按 `申请编号` 对比两表，对缺少技术记录的申请创建关联占位记录，再回读关联 ID 和 lookup；已有技术记录不得重复创建。2026-09-27 已为此前缺失的 21 条青橙申请补建技术记录，技术表与运营表均为 30 条，关联及关键运营字段回读一致。占位记录中的 `domain=qingcheng`、`execution_surface=local` 仅标明后续实施方向，不代表本地脚本已完成或调度已启用。

技术表必须保留 `domain`，不得仅凭群名、渠道名或脚本名推断部门。当前本地登记只有 `market_consultant`；未来 `qingcheng` 或其他部门必须写入独立部门值、独立配置路径和独立执行资源。

运营表记录实际业务日历。市场顾问部普通 `report_type=auto` 渠道显示为周一至周四过程、周五至周日转化；显式启用 `weekend_next_process_enabled` 的渠道，周五至周日还播报下一自然周周五期次的过程数据。技术表仍原样保留调度器兼容字段 `process_weekdays=[0..6]` 与 `result_weekdays=[4,5,6]`；具体期次和附加过程门槛以本地渠道配置及技术表的配置 JSON 快照为准。

## 权限

运营角色只需查看和编辑“运营填写”的两个简化视图，“技术配置”对运营角色必须为 `no_perm`。市场顾问部与青橙项目部分别使用独立角色，并按 `申请部门` 做相同的可读、可编辑行筛选；禁止一个部门读取另一个部门的记录。`申请部门` 对运营角色只允许新建时填写，不允许事后跨部门修改。

运营访问直接在 Base「高级权限 → 自定义角色」中管理，不走机器人审批。优先把稳定的组织部门绑定到对应角色；无法选择部门时，按已登记的人员逐一绑定，不扩大角色的数据范围。`Reader`、`普通用户` 等兜底角色对两张表保持 `no_perm`。角色规则、成员归属和不同账号的实际可见范围均需核对；仅创建角色不算权限隔离完成。

## 模板与导入

- `templates/channel_intake_base/operator_fields.json`：运营表字段，包含逐项指标选择和部门专属指标补充。
- `templates/channel_intake_base/technical_fields.json`：技术表基础字段与双向关联。
- `templates/channel_intake_base/technical_lookup_fields.json`：关键业务字段的实时查找引用。
- `templates/channel_intake_base/technical_formula_fields.json`：关联编号、上线门禁、调度状态和 `Prompt拼接` 公式。
- `scripts/export_channel_registry_records.py`：读取 `config/channels.json` 登记的全部本地渠道，输出两张表的批量记录 payload；不会修改本地配置或调用飞书。
- `scripts/read_channel_registry_request.py`：按运营记录 ID 或申请编号直接只读 Base，输出本地配置候选；不会修改本地配置、任务或外部资源。
- `config/channel_registry_base.json`：已创建 Base、两张表、运营简化视图及身份的稳定资源登记；它不保存凭证。

首次创建顺序：

1. 用 `operator_fields.json` 创建 Base 和“运营填写”。
2. 用 `technical_fields.json` 创建“技术配置”，建立双向关联。
3. 创建 lookup 和 formula 字段，并按 lark-base 指南带显式确认参数。
4. 导出并写入运营记录，保存 `申请编号 -> record_id` 映射。
5. 带该映射导出技术记录，使每行写入 `关联运营申请`。
6. 回读两张表的记录数、关联、lookup、公式和部门字段；字段值与本地配置不一致时停止，不得自动覆盖生产配置。

示例导出：

```powershell
& 'D:\anaconda3\python.exe' scripts/export_channel_registry_records.py --mode operator --output operator_records.json
& 'D:\anaconda3\python.exe' scripts/export_channel_registry_records.py --mode technical --link-map link_map.json --output technical_records.json
```

以后新增渠道时，运营先完成本部门申请并提交技术评审；技术用只读入口生成候选配置，按部门业务 Skill 审阅口径，再创建或修改本地配置。完成本地验证后才用导出器把实施结果和机器参数回写为候选差异。Base 与本地配置之间不是双向自动发布关系，任何 Base 变更都必须经过技术评审、预览和上线授权后才可进入生产配置。

直接读取示例：

```powershell
& 'D:\anaconda3\python.exe' scripts/read_channel_registry_request.py --request-id 'market_consultant/example'
```
